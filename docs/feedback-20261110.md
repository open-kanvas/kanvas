# November 10 feedback: 0.37.0

42 reports (17 from DEV, 25 from production) in one release. Each change was measured against the [mission](mission.md) yardstick: it serves the surface, fits a tempo, shortens time to clarity, and keeps intelligence with the agent. Nothing here adds a model, embeddings or inference to the server.

Owner testing steps: [testing guide](feedback-20261110-testing.md). Report IDs are the first eight characters of each report.

## Found and fixed while qualifying

Defects that no report named, found by the complete test runs of this release and fixed in it:

- **A publish could be missed by a display that was connecting at that instant.** The event stream answered before it was listening: a view published between the window's first read and the server's subscription reached nobody, and the display kept its old view until something else happened. The stream now tells the window once to read again as soon as it is really listening. This is older than 0.37.0. Regression test: `tests/core/stream-catchup.test.ts`.
- **Telemetry could be posted with a cookie that had just been revoked** (a 401 in the browser console after "sign out this browser"). Telemetry now waits while the sign-in is in doubt: after a request that changes or ends a sign-in, and after any refused request.
- A dismissed notification could flash back on the window where it was closed (`1559c2fd`).
- On a narrow screen every Tool Detail parameter type was one character wide (`7e7fb1b1`).
- Monitor-stream events were bounded per stream and per account but not for the whole server (`f4373691`).

## Compatibility

- **Checklists:** `items` is a by-id patch. Callers that relied on omission to delete must use `removeIds` or `mode: "replace"` with `allowRemove: true`. The update response is a change report, not the whole document.
- **JSON:** views without `view` now open as raw text.
- **Session state:** `updates` and `interactions` are shortened by default.
- **Limits:** `LIMIT_REACHED` for sessions and views became `SESSION_LIMIT_REACHED` and `VIEW_LIMIT_REACHED`; other limits keep `LIMIT_REACHED`.
- **Guidance blocks:** conditional by default. The report proposed `full` as the default with `concise` as an option; its later amendment and the time-to-clarity report require that nothing is repeated between first contact and a change, so conditional is the default and `full` is the declared option. `KANVAS_GUIDANCE_DEFAULT=full` sets the installation default.
- **On-screen navigation:** procedure, recipe, itinerary and sing-along need `showControls: true` to show buttons.
- **Weather:** descriptions longer than 400 characters are refused on new submissions; stored ones still render, cut to four lines.
- **Chess:** pieces given with `side` swap tone (first is now White). Pieces given with `color` are unchanged.
- **Diagrams:** small diagrams render larger on large screens.
- **Toasts:** `severity` has no schema default; omitted means info as before.
- **Font picker:** curated families with a variable edition are requested as `/api/picker/fonts/<family>/variable.woff2`; a pre-cache directory filled by hand for an earlier build needs those files (the pre-cache script writes them).
- New configuration: `KANVAS_WEBSITE_URL`, `KANVAS_LIMIT_CONTACT`, `KANVAS_GUIDANCE_DEFAULT`, `KANVAS_PICKER_PROXY`, `KANVAS_PICKER_CACHE_DIR`, `KANVAS_ICONIFY_API`. All optional.

## Storage

No SQL migration; schema version unchanged. New document kinds, all additive: `checklist-revision`, `task-list`, `task-list-request`, `session-mode`, `guidance-preference`, `account-agent`, `friction-day`, `monitor-stream`, `monitor-stream-request`. Existing kinds gain optional fields only (`toast.groupId/type/severityStated`, `display-history.label`, `view-pin.title/template`, `interaction.source`). `toast-dismissed` gains one record per account and session beside the existing per-window records. Monitor-stream events are never stored. Nothing prunes or rewrites audit or event history; only `friction-day` aggregates older than 90 days and expired `monitor-stream` rows are removed.

Rolling back to 0.36.0 needs no downgrade. The older release ignores the new kinds and fields; it cannot render the seven new templates, shows JSON as a tree, and treats `checklist.update items` as a full replacement again.

## Not done, or done differently

Each line says whether the report required the missing part. Nothing below is counted as done.

Required by a report and not complete:

- `e011b35b` (wider catalogue): the code path is complete and tested, but the catalogue only exists where an Iconify API is running and `KANVAS_ICONIFY_API` points at it. No Iconify API is installed by this release, so on an installation without one the pickers offer the five core sets (about 12,000 icons in their default styles) and say plainly that the catalogue is not configured.
- `8f4962dc`, `e2573eca`: what each client (ChatGPT, Claude, Grok) actually displays after these changes could not be observed from the isolated environment; it needs a check on real clients.
- `042944fe`: the reopen time on a real phone is not measured here; the diagnostic event `privacy-verified` makes it measurable on the owner's phone.

Asked for as optional, a suggestion or "nice to have", and not done:

- `06ee64d1`: selecting a row in `tool-call-log` does not open the details view.
- `ebebd25c`: no token-export operation (the exact values of what is shown are in the stored view); the theme mode is an OKLCH tonal scale, not Material's HCT.
- `f4373691`: no template binding that refreshes from a stream.
- `aa19719e`: the invitation does not rotate examples.
- `aef9fccb`: no note on how long delivery normally takes (sending again is offered).
- `e011b35b`: font pairings are given as fonts two at a time rather than suggested by Kanvas; seven curated families have no variable edition because none is published.

Done differently from the wording of a report, on purpose:

- `a38d9e45`: highlight is a checklist field (`data.highlight`, `highlightId`), not `view.selection`; the validation error now says why.
- `0875e953`: guidance blocks are conditional by default and `full` is the declared option (the report proposed the reverse; its later amendment and `aa19719e` require that nothing repeats between first contact and a change). Mode does not change automatically back from ambient; it needs one call.
- `6d119fd6`: `list` carries examples only with `examples: true`; `needs_template` has no resolution reference because nothing is stored and the agent must send data in the chosen shape. The one-line description pass covered session.create, session.state, checklists, toast and the new operations, as the report's incremental sequencing allows; the remaining operations keep their current descriptions.
- `f7374ccd`: `submit` keeps its clear error for a singular `displayId` (the report accepted either).
- `e2ba79e1`: the display is read-only (ticking goes through the agent) and done items always sort last; the report asked for neither an on-screen tick nor an option to keep done items in place. A list's own status colours are chosen when it is created and cannot be changed afterwards; a filter on an own column is written `column=value`. Both follow from the size limit on the published tool contract (below).

Left alone because the report said so, or because nothing needed changing:

- `2a3bdc12`: the display tap path was already per item.
- `a416fadc`: flashcards, planner and kanban already accept deltas.
- `bebc556b`: no thinning of weather points; the density decision was deferred by the report.
- `1668dad7`: duplicate consecutive history entries are not collapsed (noted and deferred by the report).
- `32b32d20`: there is no enforced minimum text size; a dense diagram still shrinks to fit unless `textScale` or zoom is used.
- `f4373691`: events are lost on server restart by design (live only).

## Contract size: no room left

Two existing limits on what Kanvas publishes to agents are now nearly full, and three choices in this release were made to stay inside them rather than raise them:

- The complete view schema (`get` with `expand: "full"` on a template that can hold any view) must fit one tool result of 96 KiB. It is 3 bytes under.
- The twelve-tool definitions have an allowance per operation. They are 19 bytes under.

Consequences in this release: icon search narrows the catalogue inside the query text instead of a separate field; task-list colours cannot be changed after creation; column filters are text entries instead of a map. The next template field or operation argument will not fit. Raising a limit, or splitting the full-union answer, is a decision for the maintainers and was not taken here.

## Website follow-up (separate repository, not part of this release)

For the "What is Kanvas" section, in the site's minimal style, the first two paragraphs of the mission:

> Kanvas is your agent's screen. It is a visual surface for people and their agents: any browser, any size, with no intelligence inside; the intelligence lives in the agent. Sometimes the screen is a whiteboard in a live conversation, sometimes a board the agent keeps up for you, sometimes a sign it sets and leaves.
>
> The experience at the heart of it is the feeling of working with a colleague at a whiteboard: you talk, the relevant thing appears on the screen while you speak, you point at it, it changes. Nobody asks permission, nobody narrates the mechanics, and your words get shorter because the detail is already visible. Templates, operations and schemas are how Kanvas is built; this rhythm is what it is.
