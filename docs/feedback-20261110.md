# November 10 feedback: 0.37.0

42 reports (17 from DEV, 25 from production) in one release. Each change was measured against the [mission](mission.md) yardstick: it serves the surface, fits a tempo, shortens time to clarity, and keeps intelligence with the agent. Nothing here adds a model, embeddings or inference to the server.

Owner testing steps: [testing guide](feedback-20261110-testing.md). Report IDs are the first eight characters of each report.

## Reopening, notifications, checklists, presence

| Report | What changed |
| --- | --- |

## Compatibility

- **Checklists:** `items` is a by-id patch. Callers that relied on omission to delete must use `removeIds` or `mode: "replace"` with `allowRemove: true`. The update response is a change report, not the whole document.
- **JSON:** views without `view` now open as raw text.
- **Session state:** `updates` and `interactions` are shortened by default.
- **Limits:** `LIMIT_REACHED` for sessions and views became `SESSION_LIMIT_REACHED` and `VIEW_LIMIT_REACHED`; other limits keep `LIMIT_REACHED`.
- **Guidance blocks:** conditional by default. The report proposed `full` as the default with `concise` as an option; its later amendment and the time-to-clarity report require that nothing is repeated between first contact and a change, so conditional is the default and `full` is the declared option. `KANVAS_GUIDANCE_DEFAULT=full` sets the installation default.
- **On-screen navigation:** procedure, recipe, itinerary and sing-along need `showControls: true` to show buttons.
- **Weather:** descriptions longer than 400 characters are refused on new submissions; stored ones still render, cut to four lines.
- **Chess:** pieces given with `side` swap tone (first is now White). Pieces given with `color` are unchanged.
- **Diagrams:** small diagrams render larger on large screens.
- **Toasts:** `severity` has no schema default; omitted means info as before.
- New configuration: `KANVAS_WEBSITE_URL`, `KANVAS_LIMIT_CONTACT`, `KANVAS_GUIDANCE_DEFAULT`, `KANVAS_PICKER_PROXY`, `KANVAS_PICKER_CACHE_DIR`. All optional.

## Storage

No SQL migration; schema version unchanged. New document kinds, all additive: `checklist-revision`, `task-list`, `task-list-request`, `session-mode`, `guidance-preference`, `account-agent`, `friction-day`, `monitor-stream`, `monitor-stream-request`. Existing kinds gain optional fields only (`toast.groupId/type/severityStated`, `display-history.label`, `view-pin.title/template`, `interaction.source`). `toast-dismissed` gains one record per account and session beside the existing per-window records. Monitor-stream events are never stored. Nothing prunes or rewrites audit or event history; only `friction-day` aggregates older than 90 days and expired `monitor-stream` rows are removed.

Rolling back to 0.36.0 needs no downgrade. The older release ignores the new kinds and fields; it cannot render the seven new templates, shows JSON as a tree, and treats `checklist.update items` as a full replacement again.

## Not done, or done differently

- `a38d9e45`: highlight is a checklist field, not `view.selection`.
- `2a3bdc12`: the display tap path was already per item; it is unchanged.
- `a416fadc` scope note: flashcards, planner and kanban already accept deltas and were not changed.
- `32b32d20`: there is no minimum readable size; a dense diagram still shrinks to fit unless `textScale` or zoom is used.
- `bebc556b`: no thinning of weather points; the density decision was deferred by the report.
- `06ee64d1`: selecting a row in `tool-call-log` does not open the details view.
- `ebebd25c`: no token-export operation; the theme mode is an OKLCH tonal scale, not Material's HCT; shade cells show their value as a tooltip and in the stored view, not printed in each cell.
- `e011b35b`: no Iconify catalogue, no variable fonts, no pre-cache script. Font pairings are given as fonts two at a time; weights are those of the curated family.
- `e2ba79e1`: status colours come from three ready-made palettes; a custom value-to-colour map, a per-list option to keep done items in place, and on-screen ticking are not part of this release.
- `f4373691`: no template binding that refreshes from a stream; events are lost on server restart by design.
- `d630abcc`: session overviews do not yet show the creating agent; `kanvas.agents.read` with `agentId` lists the sessions each agent created.
- `6d119fd6`: `list` carries examples only with `examples: true`; `needs_template` has no resolution reference because nothing is stored and the agent must send data in the chosen shape. The description pass covered session.create, session.state, checklists, toast and the new operations, not all 186.
- `0875e953`: mode does not change automatically back from ambient; it needs one call.
- `aa19719e`: the invitation does not rotate examples.
- `8f4962dc`, `e2573eca`: what each client displays could not be observed from the isolated environment.
- `042944fe`: timing on a real phone is not measured here; the diagnostic event makes it measurable.

## Website follow-up (separate repository, not part of this release)

For the "What is Kanvas" section, in the site's minimal style, the first two paragraphs of the mission:

> Kanvas is your agent's screen. It is a visual surface for people and their agents: any browser, any size, with no intelligence inside; the intelligence lives in the agent. Sometimes the screen is a whiteboard in a live conversation, sometimes a board the agent keeps up for you, sometimes a sign it sets and leaves.
>
> The experience at the heart of it is the feeling of working with a colleague at a whiteboard: you talk, the relevant thing appears on the screen while you speak, you point at it, it changes. Nobody asks permission, nobody narrates the mechanics, and your words get shorter because the detail is already visible. Templates, operations and schemas are how Kanvas is built; this rhythm is what it is.
