# November 14 feedback: 0.38.0

22 reports (12 from DEV, 10 from production) in one release. Two of them ask for the same change, so there are 21 changes. Owner testing steps: [testing guide](feedback-20261114-testing.md). Report IDs are the first eight characters of each report.

Each change was measured against the [mission](mission.md) yardstick. The four answers stand beside each group below: **surface** (does it serve the surface rather than add an application), **tempo**, **clarity** (time to clarity), **agent** (does intelligence stay with the agent). Nothing in this release adds a model, embeddings or inference to the server.

## Breaking changes

| Change | Effect |
| --- | --- |
| `source` and `showSource` removed from every view (`5134662f`, `3f65409f`) | A view that carries either field is refused with "Unsupported field". There is no compatibility shim and no migration, by owner decision. Stored views from 0.37 that carry the fields still render (the fields are ignored on screen); patching or republishing them requires dropping the fields. Per-image `source`/`showSource` in `image-gallery` are removed too. |
| Pointing is on by default (`b0be5612`) | A session that never configured pointing now has it on. A session whose owner explicitly turned it off stays off. |
| Task list order (`08d22167`) | Checked items stay where they are. `doneLast: true` restores the old behaviour for a list. |
| Choropleth (`f430f4e8`) | The Natural Earth credit and the small-territory note are no longer drawn. `territoryNote: true` shows the note. |

## Monitor streams

Surface: yes, a view that follows a stream, no dashboard product. Tempo: kept-up. Clarity: the screen is current without anyone asking. Agent: Kanvas pairs and counts by fixed rules; it interprets nothing.

| Report | What changed |
| --- | --- |
| `5dc1b2f7` | New template `monitor-stream`, bound to a stream of the same session by `data.streamId`. Published once, the screen follows the stream by itself: the browser's request is held until an event arrives (bounded waiting, no agent round-trip, no polling loop through the agent). Rows are newest first with time (reporter's timestamp, delay to receipt when it differs), source, tool or event, target/command and note. A start and its end for the same call become one row with a duration; a start without an end is shown as *no result*. Sources are colour-coded and filtered with the normal `selection`. The header shows the stream's own counters. The screen says when the stream has expired or been revoked. `title` and `note` stay with the agent. Anything shaped like a stream address is redacted when an event arrives and again before display. See [monitor streams](integration/monitor-streams.md). |
| `6e97c8aa` | The application has no user-agent filter: an isolated test posts with Python urllib, requests, Node, Go and curl agents and gets `202`. The `403` seen on DEV is produced in front of Kanvas. Changes on the application side: every stream answer carries `X-Kanvas-Stream: 1` so an edge refusal is recognisable; a recently ended address answers `410` (it answered `404` once swept); status codes, a curl + urllib smoke test and the path-scoped edge exemption are documented. **The edge exemption itself is an infrastructure change and is not part of this release.** |

## Source and info

Surface: yes, less chrome. Tempo: all. Clarity: more room for the view. Agent: provenance is something the person asks the agent.

| Report | What changed |
| --- | --- |
| `5134662f`, `3f65409f` | The source/info footer and the "Source & info" button are removed from every renderer, with the `ViewInformation` component and its styles. `source` and `showSource` are removed from the view schemas, the publish input, every example and all guidance. Renderers that used `showSource` to reveal supplied metadata: a document's page/section and a now-playing observation time now follow `showCaption`; dataset row-count summaries under numbers, charts and tables and the "Supplied text" label are no longer drawn. Dataset records keep their own provenance for the agent; it is never rendered. Item-level text fields that happen to be called `source` (a notification's sender line, a task's origin note) are content, not the footer, and are unchanged. |

## Split screen

Surface: yes, several views on one surface. Tempo: live and kept-up. Clarity: the layout a person asks for in one publication. Agent: the agent chooses rows and columns; Kanvas lays out exactly that.

| Report | What changed |
| --- | --- |
| `a3523838` | `rows` × `columns`, each 1-4, filled row by row: 1×3, 3×1, 1×4, 4×1 up to 4×4. One level of nesting: a top-level pane may hold its own grid (`{id, rows, columns, panes}`); nested panes cannot be split again. At most 16 panes in total. Phones show the authored panes; the tab fallback is gone and nothing restricts the pane count below the cap. Stable pane ids (unique across the screen), single-pane patch paths (`/data/panes/1/panes/2/view` for nested) and the shared byte/node limits are kept. Without `rows`/`columns`, 2, 4 and 6 panes lay out as in 0.37 and 3 panes form a lane. See [split screen](templates/split-screen.md). |
| `4e78197e` | Optional `divider`: `"none"` for edge to edge, or `{gap, borderWidth, borderColor}`. Omitted, the default is exactly the 0.37 gap and border. Applies to nested grids. |
| `4b998939` | Pie and donut measure the pane: the key goes beside the plot when the area is wider than tall, the plot gives way to the key otherwise, and a long key scrolls inside itself. The chart no longer scrolls in a landscape pane. |
| `ee486423` (part) | The description ("Two to six views") and the validator ("2, 4 or 6") disagreed; both now state the grid rule. |

## Pointing

Surface: yes, pointing at the whiteboard; no buttons, selections or forms are added. Tempo: live. Clarity: "this one" needs no description. Agent: Kanvas reports where; the agent decides what it means.

| Report | What changed |
| --- | --- |
| `b0be5612` | On by default in every session, no activation and no button. A tap or click leaves a named mark that fades after about four seconds; a long press or double tap pins it until its author points elsewhere. Each gesture records a semantic anchor where there is one (text span, table cell, chart mark, image position) and always the place as a fraction of the view, plus what the browser read under the point (role, label, context, pane). What was pointed at reaches the agent in a `pointing` block on its next response, whatever it calls, once per connection and only when there is something new. Marks reach other participants through the session's event stream instead of a 650 ms poll. The on-screen Point button with span selection remains available with `tools: true`. See [pointing](sessions/pointing.md). |

## Message board

Surface: borderline by nature; kept to operations and one snapshot view, no board UI, no threads. Tempo: kept-up. Clarity: one place to ask. Agent: reading, summarising and deciding what to post stay with the agent and the person.

| Report | What changed |
| --- | --- |
| `d25aaee4` | A public message board for all users of an installation: `kanvas.board.post`, `kanvas.board.read`, `kanvas.board.overview`, `kanvas.board.update`. Text, a self-chosen public name, a time and up to five tags. The first post returns a disclosure and posts nothing until the person has agreed and chosen a name. Messages never carry an account id, email address, session or agent detail. Full-account grants only; no anonymous access. Ten posts an hour and thirty a day per account, 2000 characters, newest 5000 messages kept. Per-account "seen up to here" mark; `newOnly` returns what is new. Opt-in notice at the start of a conversation or session. New `message-board` overview template; messages render with the existing `chat` template. Stored as ordinary documents: no schema migration. See [message board](integration/message-board.md). |

## Text size

Surface: yes. Tempo: all. Clarity: readable from across the room without touching each view. Agent: a setting, nothing inferred.

| Report | What changed |
| --- | --- |
| `0448f65b` | New session and account setting `textSize` (percent of standard, 50-250). Every template responds. Reference views (task list, tables, lists, logs, documents, messaging, the colour, icon and font pickers) scale all of their content and lay it out again in the same area, scrolling where they already scroll. Views composed to fill the screen (a fact, a number, a chart, weather, signage) are laid out for a proportionally smaller or larger screen, the way browser zoom works, so their fixed-size text changes while content sized to the screen keeps filling it instead of being cut off. It multiplies with per-window zoom, which stays per window and unsaved. `readingFontSize`, `readingWpm` and `readingZoom` stay scoped to documents. The settings view offers "Text size (all views)". The font picker takes `sampleSize` in CSS px. |

## Connecting hosted clients

| Report | What changed |
| --- | --- |
| `99bc5479` | **No server defect was found and no flow change was made.** Evidence available: on production on November 12 a Grok token exchange returned 200 and a later `GET /mcp` returned 404; there is no conclusive cause. A new test records what the transport answers to each request a hosted client makes after sign-in (initialize, `notifications/initialized`, `GET` with a session, `GET` with an unknown session, `GET` without a session, no bearer, `DELETE`) and checks them against the MCP specification; the results are in the handoff. Why Grok does not list the connector remains open and needs the server-side request sequence of a fresh attempt. The email-confirmation stall ("stopped at email confirmed") matches the documented design, in which the browser that started the request completes it and the browser that opened the email link only confirms; an in-app browser that is closed when the person switches to their mail app cannot complete. That is recorded as a usability finding, not fixed here. |

## Contract size

The published contracts had almost no room left in 0.37. No existing limit was raised.

- **Presentation contract** (the largest single MCP result, limit 96 KiB): the two new templates would have put it 434 bytes over. `monitor-stream` and `message-board` are therefore display views and split-screen panes, **not presentation slides**, at validation time and in the published schema alike. The compact contract measures about 97.7 KB; `tests/core/feedback-20261114.test.ts` and `tests/rendering/schema-compaction.test.ts` hold the limit.
- **Tool listing**: the established allowance of 960 bytes per inventoried, real-client-tested new operation is applied to the four message-board operations (`tests/mcp/nov14-mapping.ts`). Measured 179003 bytes against a cap of 179712.
- Removing `source`/`showSource` freed little: the compacted schema already shared those fields between templates.

## Storage, migration, rollback

- **No SQL migration.** `DATABASE_SCHEMA_VERSION` is unchanged. New document kinds: `board-message`, `board-reader`. Existing kind `pointing-settings` gains an optional `tools` field; `monitor-stream` rows are unchanged.
- **Rollback to 0.37** needs no data change: board rows are ignored, the `textSize` setting is ignored, and split-screen or `monitor-stream` views published by 0.38 that 0.37 cannot validate keep rendering as stored views only if their template exists there; a `monitor-stream` or `message-board` display and a grid 0.37 does not know show "could not be displayed" until republished.
- **In memory only**, bounded, lost on restart: pointer marks, the pointing queue (30 gestures per session, 10 minutes), per-connection delivery cursors (5000 connections), monitor-stream tombstones (500) and waiting requests (64 per stream, 1024 in total).
