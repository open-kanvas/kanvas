# Supplied instrument visuals

`template:"instrument"` renders two families. Nothing captures or generates audio, MIDI, video, recognition, chords or fingerings. The agent supplies all pitches and labels. No musical correctness is inferred from the picture.

Keyboard configuration: `{family:"keyboard",firstMidi:60,lastMidi:83}`. MIDI 60 is C4; chromatic coordinates and black/white keys are fixed mechanical layout. Element IDs `key:60`, `key:63`, etc. Supply `pitch:{midi:63,label:"Eb4"}` to retain enharmonic spelling; otherwise the key shows its MIDI number. Range is at most 61 keys. One keyboard/manual per view; use separate displays for paired instruments.

Fretted configuration: `{family:"fretted",strings:[{id:"highE",label:"E4",openPitch:{midi:64,label:"E4"}},...],firstFret:0,fretCount:6,capo:0}`. Strings render top-to-bottom in supplied order. Conventional guitar order is **E4, B3, G3, D3, A2, E2**, highest first; low-to-high appears upside down. `handedness:"left"` mirrors fret direction and the nut horizontally without reversing strings or changing element IDs; `"right"` is the default. Re-submit the configuration to change handedness. Neutral body/lines follow the display theme; highlights use the user/session accent unless an element supplies an explicit hex override. Stable IDs `string:lowE:fret:0`, `string:lowE:fret:2`, `string:lowE:mute`. Fret numbers are physical frets, not capo-relative. `firstFret`/`fretCount` bound the visible region; fret 0 is the open-string marker. Capo is a labelled physical location, not transposition logic. Supply the resulting note pitches/labels yourself. Guitar, bass and ukulele use six/four/four strings with supplied tuning; up to 12 strings supported. No chord library or fingering inference.

Elements are a record `{id:{highlight:true,color:"#38bdf8",label:"optional",finger:"2",pitch:{midi:64,label:"E4"}}}`. Highlight false preserves an annotation without a colored marker. Use `kanvas_publish` operation `patch` with `operations:[{op:"instrument",changes:[{id:"key:60",value:null},{id:"key:64",value:{highlight:true,pitch:{midi:64,label:"E4"}}}],label:"E major"}]`. Every value replaces only that addressed element's complete visual state; null clears. All changes are atomic; unknown/out-of-range targets, duplicate targets and keyboard pitch/coordinate mismatches reject the whole batch. Configuration and unrelated highlights persist. Read full state/revision with `kanvas_inspect` operation `display.current`; use expectedRevision and a new requestId. Exact retries are durable/idempotent.

Optional `frames:[{id:"c",durationMs:1000,elements:{"key:60":{highlight:true}}},...]` provides complete highlight snapshots (not accumulated deltas) with stable frame IDs. A single submit with frames plus playing playback/actual UTC startedAt runs locally. `op:"instrument-sequence"` has append/replace-future/replace/pause/resume/seek/clear and accepts frames for queue actions, positionMs for seek. Same persisted clock, completion, hidden-tab/reconnect catch-up and retry semantics as [captions](live-captions.md). Frames override static elements; clear freezes the currently visible highlights into static elements, permitting subsequent narrow updates. Static element operations reject while any frames remain, avoiding silently hidden edits. Completion holds last frame. No audio synchronization guarantee; 100ms visual polling is for instructional paced steps (minimum duration 250ms).

No dependencies or migration. `KANVAS_INSTRUMENTS_ENABLED=false` independently rejects new instrument publications/edits (including slides); existing stored visuals remain readable. The instrument feature can be disabled while retaining stored data. Mobile uses horizontal scrolling rather than shrinking keys/frets unreadably. Desktop/phone automated receiving tests do not replace owner's voice conversation and across-room readability acceptance. Wind, percussion, mallets, fretless, staff/tablature, multi-manual keyboards and chord presets are not part of this deliberately narrow release.
