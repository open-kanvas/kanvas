# Satisfaction kiosk
Native satisfaction template: surveyId, levels3(default) or5, optional question/thankYou, thankYouSeconds(.5–10), closed. Three faces map1,3,5; five map1–5. Every successful tap has server timestamp and independent response; not unique visitors. Existing revision/requestId dedupe/CAS and session/display authorization apply, with500ms per-principal/display rate limit. Rejected submissions are not counted. No pending-action inbox burden.

Discover kanvas.satisfaction.read with kanvas_discover {catalog:"operations",action:"get",id:"kanvas.satisfaction.read"}, then execute through kanvas_call {operationId:"kanvas.satisfaction.read",arguments:{...}}. Supply sessionId, optional displayId/surveyId, explicit ISO from/to with offsets, positive range<=366days. Returns counts1–5,total over [from,to); editor only, never scoped/capture credentials. Stored additive satisfaction-response documents use existing database/schema; no migration. Existing interaction records acknowledged automatically.

Public kiosk: provision an existing interactive display-scoped share/pairing in a separate browser profile, then open /kiosk/{sessionId}/{displayId}. The general kiosk route accepts authorized full-account viewers or a matching display-scoped grant, but rejects capture and mismatched scoped access. Read-only grants cannot submit responses. Never leave owner credentials on public hardware; use a separately approved interactive display-scoped browser. No menus, ordinary DeviceReceiver navigation or ReauthenticationPrompt are mounted. Expiry, revocation or loss of the live connection makes the kiosk unavailable. The route can render other authorized templates too; changing away from a satisfaction view ends survey collection on that display. No app exit is exposed: administrator exits/revokes via authenticated separate device/account. Browser address bar, OS gestures, external navigation and keyboard shortcuts cannot be locked by this route; actual managed OS kiosk deployment remains operator work and unverified. Do not claim OS lockdown.

Independent flags KANVAS_SATISFACTION_ENABLED=false rejects collection server-side, VITE_KANVAS_SATISFACTION=false hides renderer after rebuild. Aggregates remain readable; rollback retains saved documents. Source rollback cannot render new views; prefer flags. Responses retain existing user-linked interaction metadata: totals omit identities, but this is not an anonymous-data collection claim.
