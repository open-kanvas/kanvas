# Signage library

Native `signage` view with reviewed, unmodified Google Material Symbols artwork (Apache-2.0). Retain the bundled licence, notices and per-file provenance; see [reviewed signage artwork](../signage-artwork.md). Not certified or official ISO/ANSI/BS/NS symbols; independent local content/compliance review is required before operational use. Region variants coexist as metadata and generic labels, not a claim that all local artwork variants are implemented.

Read `kanvas_discover {catalog:"templates",action:"get",id:"kanvas.template.signage"}` to inspect allowed type, region and direction values in the schema. Complete per-sign provenance is in `/signage/manifest.json` and `/signage/credits.html`, not a returned discovery catalog object. Publish `{version:1,template:"signage",data:{items:[{id:"restroom",type:"restroom",direction:"right"}]}}`. The reviewed catalog has 88 types backed by 55 SVGs; retired safety/traffic types (including exit) are not accepted. Legacy shop-sign templates and their signage.update operation remain unchanged; use ordinary show/replace_data/view.patch for this new library.

Data: region international/us/uk/no; text english(default)/none; items1–6, unique stable IDs, catalog type, optional per-item region, direction, label80chars, caption160chars. Visual-only suppresses visible labels and captions but retains accessible labels. Directions: ahead/up/left/right/down, four diagonals, four90-degree turn arrows. Only types supporting directions accept them; consult the current type contract. Retired safety/traffic artwork is not available.

Existing revision-bound atomic view.patch updates /data/items or specific fields; retries and history are unchanged. Use current IDs/state to locate an item before array-index updates. A single sign fills the display; groups adapt columns to portrait/landscape/square. Extreme text may become small; concise captions are recommended.

Disable this optional renderer independently with client-build `VITE_KANVAS_SIGNAGE=false` and rebuild. This does not disable server publication or delete stored content. Persistence is additive ViewSpec JSON, no migrations. Source rollback leaves views/history stored but older code cannot render this template; prefer the flag if historical access matters.

Dynamic directory/map/status/queue/hotel/office/real-estate families are included below. Satisfaction and traffic-demo are separate templates; neither is an OS kiosk-lockdown or real traffic-control capability.

## Dynamic and noninteractive families

The catalog includes status/queue/meeting rooms, studios, offices/Wi-Fi, hotels, building directory and real estate, plus wayfinding and parking. Rights-conflicting safety and traffic artwork is excluded; never infer that an old type remains supported.

- `value` exact supplied text/number; `status` open/closed/available/occupied/full; `details` up to4 {label?,value} entries for next booking, expected fix time, allowed parking hours, company/plate, hotel hours, dates, prices, phone and agent. Update without replacing whole view using revision-bound view.patch. Parking-free numeric values must be nonnegative integers; waits nonnegative.
- `image` absolute public HTTP(S) company/agent logo URL (protected /api/assets and /api/media are not supported). No imagery copied or generated by the feature.
- `endsAt` on live-countdown: supplied ISO datetime, displays remaining seconds and clamps to0; uses receiving server-time offset if provided, recomputes after throttled tabs from absolute time, no completion action.
- `directory` on building/floor/tenant/room-allocation: {layout:"by-floor"|"building"|"single-floor",floor?,entries:[{id,name,floor,room?,description?,direction?}]}. Single-floor requires exact floor. Max24 supplied entries, uniqueIDs. Building mode is a simple floor-shaped reference, no automatic building geography. Long references can scroll rather than omit tenants. Adding/removing/moving uses whole entries-array set or revision-bound leaf edits.
- `destinations` on walking-time: up to8 {id,label,minutes,direction}; explicit minutes, no routing/distance calculation.
- `map` on you-are-here: {youAreHere:{x,y},areas:[{id,label,x,y,width,height}]} in explicit0–100 schematic coordinates, max24 areas, bounds checked. No inferred mall layouts or map accuracy.
- `wifi`: {ssid,security:"WPA"|"WEP"|"nopass",password?,hidden?,showPassword?}. Encodes supplied credentials in a conventional WIFI QR payload, escaping delimiters. Secured networks require password; open networks reject one. Password text hidden unless showPassword:true, but QR deliberately shares it with viewers—do not publish credentials to unintended audiences. No automatic connection or network validation.
- Visual-only mode suppresses labels/captions/details/directory names/destination prose, retaining pictogram; schematic map labels suppressed, QR remains. Data-rich directory meanings inherently require supplied names; use English mode to show them.

Examples: meeting-room status occupied + Next booking detail; out-of-order + Expected fix; parking-free value12; now-serving value"A42" with Estimated wait detail; waiting-time value8; hotel restaurant status open with hours details; open-house details date/time/phone/agent and image logo. Available door/hotel variants use their reviewed Material Symbols artwork. English labels can be explicitly overridden.
