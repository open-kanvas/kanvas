# Live Captions — supplied text, local playback

Distinct from transcription (unchanged). Publish `template:"live-captions"` with `data.chunks:[{id,text,durationMs}]` (unique stable IDs, ≤1000 chunks, ≤400 characters each, 250–120000 ms). Agents choose natural breaks, typically 15–30 words, and reading-time dwell. No speech recognition, translation, audio, or inferred segmentation.

One submit can contain the entire schedule and `playback:{state:"playing",positionMs:0,startedAt:"<actual UTC start>"}`. Omission starts paused; `kanvas_publish` operation `patch` with `operations:[{op:"sequence",action:"resume"}]` anchors the clock on the server. All patch calls require current `expectedRevision`, unique `requestId`, sessionId and displayId. Read `kanvas_inspect` operation `display.current` for full queue, revision and computed `sequenceStatus` (not proof of paint).

Sequence actions: `append` with chunks retains past/current and anchor; `replace-future` keeps through current chunk and replaces only following chunks; `replace` installs chunks paused at zero; `pause` freezes exact position; `resume` continues; `seek` requires positionMs within duration, retaining running/paused state; `clear` empties and pauses. New chunks after completed running playback start at arrival, not in the expired past. Completion holds the last caption. Exact retries cannot append twice. Replace+resume can be one atomic patch. Generic field patches remain available for explicit correction of chunk text/duration.

Running time is persisted UTC anchor plus position, evaluated locally using the existing server time reference and monotonic elapsed time. Hidden tabs and disconnected receivers continue the logical timeline, catch up on visibility/reconnect, and skip expired chunks; no per-chunk network requests. A fresh server snapshot corrects clock offset; network transit can introduce small visual skew. This is reading-paced display, not audio synchronization. Preview is static. A replacement publication intentionally resets to its submitted state. An empty sequence is blank. Transcription retains full history independently.

No database migration or dependencies. `KANVAS_CAPTIONS_ENABLED=false` independently rejects new caption publications/edits (including nested slides); already stored views remain readable and data is never deleted. Revert this additive template commit to disable the capability; retain persisted view data for re-enabling. Acceptance still needs the owner's across-room readability and real voice-agent workflow review. Screen-reader auto-announcement is intentionally off to avoid speaking every scheduled chunk; the visible text remains accessible. Reduced motion disables transitions.
